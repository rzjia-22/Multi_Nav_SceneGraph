# Multi Nav SceneGraph

ROS 2-native real-time navigation and online 3D scene-graph reconstruction for
one or many heterogeneous robots. Navigation, mapping, simulation and motion
execution are independent modules connected by standard ROS interfaces.

The two validation rosters are generated by the same launch system:

- Phase 1: one Unitree Go2, one selectable navigator and one Hydra pipeline.
- Phase 2: two Go2 and two kinematic UAV sensor platforms, each with an
  independent namespace, TF tree, mission state and Hydra pipeline.

The project deliberately does not fuse scene graphs. Every robot owns its map
frame and DSG output; this is the stable boundary for future fusion research.

| Hydra | `2e58a35baea629eee8838409771876acff015daf` |
| Isaac Sim / Isaac Lab | 5.1.0 / 2.3.1 |
| ML image | PyTorch 2.7.1 + CUDA 12.8 wheels |
| DDS | Cyclone DDS, host networking, domain 42 by default |

Hydra's complete source graph is pinned in `upstream.repos`. The Isaac process
uses the Jazzy client libraries bundled with Isaac's ROS bridge and publishes
only standard message types; project ROS nodes run in the robotics image.

## CPU-only quick start

The synthetic publisher exercises the complete ROS 2, navigation and Hydra
composition without Isaac or a GPU. It is intended for integration tests, not
reconstruction-quality evaluation.

```bash
make robotics-image
make build
make phase1-synthetic
```

In another terminal, run the machine-readable acceptance observer:

```bash
make accept-phase1
```

Run the four-robot topology and its observer with:

```bash
make phase2-synthetic
# second terminal
make accept-phase2
```

Use Ctrl-C to stop the bringup. All Hydra instances save their output under
`runs/<run-id>/<robot>/hydra` and shut down cleanly.

## Navigator selection

Coverage, Diffusion and Nav2 use the same launch graph and ultimately publish
`geometry_msgs/Twist` to `cmd_vel/navigation`. The safety source and command
arbiter produce the backend-facing `cmd_vel_safe`; no navigator emits joint
commands.

```bash
MNS_NAVIGATOR=coverage make phase1-synthetic
MNS_NAVIGATOR=nav2 make phase1-synthetic
```

The original audited Diffusion and Go2 actor weights are ignored runtime
assets. Fetch and verify them, build the optional ML layer, then run Diffusion:

```bash
make models
make robotics-ml-image
make test-models
make phase1-synthetic-diffusion
```

`make models` checks both SHA-256 digests. Loading is tensor-only with
`weights_only=True`; neither checkpoint is deserialized as arbitrary Python.

## Isaac runtime

Prerequisites are a compatible NVIDIA driver, NVIDIA Container Toolkit and a
GPU meeting Isaac Sim 5.1 requirements.

```bash
make gpu-preflight       # Level 0 host + Level 1 Docker + graphics config
make isaac-compatibility # Level 2 official Vulkan/requirements report
make isaac-minimal       # Level 3 finite GPU PhysX smoke
make models
make phase1
make phase2
```

The shared Isaac world runs a deterministic collision-enabled semantic forest,
physics at 200 Hz, the Go2 velocity actor at 50 Hz and RGB/depth/semantic
publication at 10 Hz. Go2 is an articulated Isaac Lab asset controlled through
the original 48-to-12 locomotion actor. UAVs are intentionally kinematic sensor
platforms for Phase 2. Known-area Coverage consumes the same configured tree
centres as inflated obstacles; it is not an unknown-environment explorer.

The current development host passes the Level 0–3 runtime path on an RTX 4060
Laptop GPU: Docker GPU passthrough, Vulkan enumeration and Isaac Lab 2.3.1 GPU
PhysX stepping are real runtime evidence. The official compatibility checker
still reports the 8 GB VRAM and 16 GB system RAM below its recommended minimum;
multi-camera Phase 2 therefore remains resource-constrained until measured.

To validate the message payloads separately from navigation and Hydra, run the
simulation with `--enable_cameras` (the normal compose command already does),
then in another terminal run `make accept-isaac-sensors`.

The articulated motion gate is `make accept-go2-motion`. The supplied checkpoint
passes stand, forward, moving-turn, explicit-stop and deadman phases through the
public ROS boundary while cameras are active. Consult the
[development status](docs/development_status.md) before interpreting
`make phase1` or `make phase2` as full real-Isaac navigation/mapping acceptance.

## Verification and observability

```bash
make validate       # repository contracts and 17 pure unit tests
make build          # all 8 ROS packages and package tests
make test-models    # real Diffusion and Go2 checkpoint forward passes
docker compose config --quiet
docker stats --no-stream
```

Each robot publishes mission state plus Hydra input/output rates, estimated
source timestamp gaps, stale-state errors and received counts. `docker stats`
provides container CPU/memory/GPU-adjacent resource observation without adding
a monitoring dependency. Optional MCAP recording remains a side channel and is
never required by Hydra.

## Packages

- `mns_interfaces`: mission and mapping health messages.
- `mns_core`: validated robot roster, names, frames and sensor contracts.
- `mns_navigation`: coverage, Diffusion, Nav2, path following and local safety.
- `mns_motion`: Twist arbitration and backend boundary.
- `mns_mapping`: Hydra composition and mapping health observation.
- `mns_multi_robot`: thin robot-instance and mission coordinator.
- `mns_simulation`: Isaac-specific Go2/UAV runtime and synthetic test source.
- `mns_bringup`: configuration-driven Phase 1/2 launch composition.
